# ツムグ プロトタイプ用 合成データ（企画書v4対応）

舞台：わたらせ銀行（架空）太田支店｜SFAはSalesforce導入済み（想定）｜パイロット開始：2026年4月（想定）

すべて架空のデータである。実在の企業・人物とは関係ない。

---

## ファイル一覧

| ファイル | 企画書の層（12.3） | 内容 |
|---|---|---|
| `companies.json` | ① 顧客マスタ | 顧客企業10社。代表者年齢、業歴、面談相手（contacts）、支店長ビュー用の対話状況（support_status） |
| `reports.json` | ① 日報（SFA内） | 日報79件。**2026年3月以前は「過去日報（取り込み）」で本文のみ、2026年4月以降は「業務報告＋気づき欄」** |
| `employees.json` | ① 行員・担当履歴（SFA外） | 行員10名。上司（reports_to）、閲覧範囲（access_scope）、知見の領域（knowledge_areas）、文体の癖（persona） |
| `assignments.json` | ① 担当履歴（SFA外） | 誰がいつどの企業を担当したか（主担当・副担当） |
| `consultations.json` | ① 本部への相談履歴（SFA外） | 誰が誰に何を相談したか。相談先を「関係の情報」で選ぶ材料 |
| `case_cards.json` | ① 事例カード（全行共有可） | 類似事例として**表示してよい**項目だけをまとめたもの |
| `cases.json` | ① 案件記録（閲覧制限あり） | 事例の詳細。判定・表示には使わない（権限のある人が参照する原本） |
| `tags.json` | ④ 判定 | 正式タグ4＋静的要因2の定義 |
| `judgment_criteria.md` | ④ 判定 | ベテランの言葉で書いた判定基準、反応の4層ルール、権限と提示のルール。**LLMに渡すプロンプトの素材** |
| `demo_inputs.json` | デモ | デモで入力する「今日の一言」3件と、期待される反応（答え合わせ用） |

## データの関係

```
companies ─┬─ reports（company_id）── employees（employee_id）
           ├─ assignments（company_id, employee_id, 期間）
           └─ consultations（company_id または case_id）
case_cards ── cases（case_id）  ※表示は case_cards のみ
employees ── employees（reports_to：上司）
```

## 権限の想定（access_scope）

| 値 | 対象 | 閲覧できる範囲 |
|---|---|---|
| `assigned_companies` | 法人担当 | 現在の担当先企業の全記録（**前任者の記録を含む**。企画書13.3の前提） |

## 注意

- `reference_tags` と `reference_candidate` は、LLM判定の**答え合わせ用**であり、本番のデータには存在しない。判定ロジックに入力として渡さないこと
- 静的要因（経営者の年齢、業歴）は `companies.json` から実行時に算出する（70歳以上、業歴50年以上）
- 今日の日付は **2026年9月15日** としてデモを行う想定（D2・D3は翌日以降の日付だが、デモでは続けて入力してよい）
