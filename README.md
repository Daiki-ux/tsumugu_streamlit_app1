# ツムグ（Salesforce 勘案版）— 8 ファイルで動くプロトタイプ

> **個人の習作です（2026-09-24 時点）。** チームで決まった仕様ではありません。
> チームの共有資料（企画書 v4・企画設計書・合成データ）をもとに、「試しに作ってみるとこんな感じになる」という**議論のたたき台**として作ったものです。
> 元の企画やプロトタイプから何を・なぜ変えたかは [`6_ツムグ_変更記録（パイロット版）.md`](6_ツムグ_変更記録（パイロット版）.md) にまとめています。どの判断も、チームで見直す前提です。

企画書 v4（SFA の中に表示領域を持つ）を、★3-1 の開発手順 **収集 → 貯める → 分析 → 検索・ランキング → 表示 → デプロイ** の形で実装したもの。
担当者が触るのは SFA の画面だけ（プロトタイプは Streamlit で 3 画面を模す）。LLM のキーが無くても全工程が動く。

## 起動

```bash
pip install -r requirements.txt
python docs/convert_source_data.py                  # もっちゃんの合成データ → data.json / rules.json
python database.py --reset                          # data.json → data/tsumugu.db
python crawler.py                                   # 公開の事業承継ナレッジを集める（ネット無しなら飛ばしてよい）
python -c "import tsumugu; tsumugu.retag_all()"    # 過去の記録にタグを付ける
streamlit run app.py
```
（DB が空なら app.py 起動時に上の 3 つを自動で行う。PowerShell は先に `$env:PYTHONUTF8="1"`）

## 画面（一目で分かるダッシュボード）

| 部品 | 中身 |
|---|---|
| **状態バッジ** | 反応の 4 層をそのまま出す：①予兆は出ていません（記録は蓄積しています）②過去に関連する記録があります ③これまでにない変化が続いています ④支援の検討が必要かもしれません。**点数・危険度の段階ではない**（企画書 v4 §7.2・§7.3）。文言は企業を評価する言い方を避け、「シグナルの状態」を述べる形で揃えている |
| **数字タイル** | 取引先＝予兆の種類／最終接点／類似の支援事例／面談メモ件数。日報＝重なった予兆／根拠の記録件数／事例件数／処理時間 |
| **予兆チップ** | ● 記録から拾ったもの／◆ 顧客データから（静的要因）／＋ 候補タグ（何回目か） |
| **確認事項・相談できる人・事例カード** | すべて出典つき。相談先には「直接相談する／上司に相談する」と上司の名前 |
| **面談メモ履歴** | 新しい順。担当交代の区切り入り |

取引先の画面のバッジは「**実際に出たシグナル**」を映す。蓄積だけでは先に立たない（記録をきっかけに判定が走る設計のため）。
条件が揃っている企業には「次に予兆タグの付く記録が入ると提示します」と添える。

1 日 1 ブランチ：`feature/day1-database` → `day2-crawler` → `day3-tsumugu` → `day4-app`。
